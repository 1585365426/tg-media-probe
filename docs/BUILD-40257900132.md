## 1 收藏页横屏

两个来源，都堵上：

- 视频页的横屏开关写在原生侧（`OrientationBridge` → `setMode(landscape)`），
  切走 Tab 时 `dispose` 不执行（`IndexedStack` 保活），原生侧一直停在 landscape。
  `didUpdateWidget` 里 `oldWidget.active && !widget.active` 时补
  `resetToSystem()`。
- 收藏页本身是竖屏列表，进入时显式锁 `lockedPortrait`，退出 `resetToSystem()`。
  这样即使别处留下 landscape，或者用户横向持机打开，列表也是正的。

`test/favorites_orientation_test.dart` 用 mock 的 method channel 断言
`setMode(mode=portrait)` 与退出时恰好一次 `reset`。

## 2 不能全屏

原来的结构是 `Center` + `AspectRatio`，只能居中等比缩放，16:9 视频在 19.5:9 的
屏幕上必然上下留黑。改成

```dart
SizedBox.expand(
  child: FittedBox(
    fit: BoxFit.cover,
    clipBehavior: Clip.hardEdge,
    child: SizedBox(width: width, height: height, child: VideoPlayer(controller!)),
  ),
)
```

代价是裁掉边缘（抖音同款取舍）。错误态与未就绪态各自包了 `Center`，因为外层
的 `Center` 已经拿掉。

## 5 缓存始终 0 B

`CacheManager.scan()` 只走 `thumbnailDir` / `playbackTempDir` /
`partialDownloadDir` 三个目录，而这三个目录本 App 从来不写：缩略图没做、播放器直接
打开下载区的文件、分片由 `DownloadMover` 写在目标旁边。真正的字节全在
`Library/Caches/tgmedia/tdlib_files`（TDLib 自己的 blob 池），一直没被扫。

- `CacheKind` 增加 `tdlibBlobPool`，`_dirFor` 映射到 `layout.tdlibFilesDir`
- 该目录在 temp 区内，所以每一条删除仍然过 `assertDeletableByCacheClear`
- TDLib 的数据库在 `secure/tdlib/db`，属于授权区，从 cache 路径不可达
- 清空后重建空目录，下次启动布局一致

`test/cache_clear_test.dart` 新增 2 项：扫到 5120 B、清掉后 `td.binlog` 与
`session.json` 都还在。

## 6 加载慢

只做预取，不改「整段下载后再播」这条第 4 步定下的约束（流式会让 size 校验和
分区搬迁失效）。

- `MediaResolver.prefetch(record)`：`downloadFile(priority: 1, synchronous: false)`，
  最低优先级，当前条用 32，不会饿死播放
- 跳过规则抽成纯函数 `decidePrefetch`，可在没有 TDLib 的情况下断言：
  `noFileId` / `protectedContent` / `alreadyQueued` / `alreadyLocal` / `enqueue`
- `VideoFeedPage._prefetchAhead()`：激活当前条之前，先给后面两条各发一次；同一帧
  两次请求靠 `_prefetched` 集合去重
- 客户端还没就绪时 `resolver` 抛 `StateError`，`_prefetchAhead` 吞掉它 —— 这个
  状态由激活路径负责报给用户，预取不该抢这个职责

## 8 抖音 Tab（F1：全屏沉浸）

第 4 个 Tab，不是第二套实现：

```dart
TabController(length: 4, ...)
static const int _immersiveTab = 2;
bool get _immersive => _index == _immersiveTab;
appBar: _immersive ? null : AppBar(...)
```

- 进 Tab 即隐藏 AppBar 与 Tab 条，视频占满整屏
- `randomOrder: true`：每条按 `record.key` 去重后分片洗牌，一个会话内不重复
- 返回键在沉浸态直接回「视频」Tab，而不是弹掉整个 shell
- 两个 Tab 共用同一个 `VideoFeedPage` 类型、同一套播放器槽位，「同时只有一个
  解码器」这条不变式仍然成立；离开任一视频 Tab 才由 shell 调
  `handleTabChanged` 释放

## CI 的一次失败与修法

run 40257747263 死在第一个 gate，一行 Swift 都没编：

```
*** -[_NSStdIOFileHandle writeData:]: Broken pipe
libc++abi: terminating due to uncaught exception of type NSException
##[error]Process completed with exit code 134
```

原因：`major="$(xcodebuild -version | head -1 | ...)"`。`head -1` 读一行就关管道，
`xcodebuild` 还在写 banner，拿到 EPIPE 后直接 abort。改成先整段捕获再用 `sed`
取第一行，管道不被提前关闭；顺带把「版本号解析不出来」从静默落入算术比较改成
显式失败。
