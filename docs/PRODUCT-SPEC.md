## 1. 产品定位

iPhone 上的 Telegram 私人频道视频媒体库。

```
打开 App
  → Face ID 解锁（仅在用户开启后）
  → 恢复 Telegram 登录状态
  → 频道列表
  → 抖音式全屏视频流
  → 播放 / 切换 / 横屏
```

只读原则：应用读取当前 Telegram 账号有权访问的频道与媒体，不实现云端内容修改、删除或权限绕过。这一条由 `lib/security/td_readonly_guard.dart` 在请求发出前强制执行，不是 UI 约定。

执行方式（第 4 步收紧）：三张清单——`cloudMutatingMethods`（64 项，必拒）、`readOnlyMethods`（23 项，读 + 登录/登出所需）、`localOnlyMethods`（8 项，只动本地文件）。三者均为精确匹配。**未出现在任何清单里的方法一律拒绝**，新 TDLib 方法必须先被分类才能使用；拒绝文案区分「是写方法」与「未分类」两种原因。登录与登出类方法会改服务端状态，列进白名单是有意例外：没有它们就无法登录或退出，且只在用户显式操作时调用。

## 2. 导航结构

固定在底部的三个入口，顺序不可变：

| # | 名称 | 图标语义 |
|---|---|---|
| 1 | 频道 | 列表 |
| 2 | 抖音 | 播放 |
| 3 | 设置 | 齿轮 |

- 不得出现第四个入口。
- 不得出现第二套导航（例如「抖音」页内再生一层 Tab）。
- 原来独立的图片、文件导航取消；图片与文件通过频道内的消息列表访问。
- 使用 iOS 风格 `CupertinoTabBar` 语义，iPhone 11 Pro 上需要处理刘海与底部 Home 指示条的安全区。

## 3. 频道页

内容来源：`getChats` 返回的、当前账号有权限访问的频道（`chatTypeSupergroup` 且 `is_channel`）。

列表项显示：

| 元素 | 说明 |
|---|---|
| 头像 | 频道照片；无照片时用首字占位，不生成假图 |
| 名称 | `title` |
| 媒体数量 | 已索引的视频条数；未索引完成时显示「统计中」，不显示 0 |
| 同步状态 | 已同步 / 同步中（带进度）/ 未同步 / 同步失败（可重试） |

搜索：按名称过滤，本地匹配已索引数据，不发起云端搜索。

进入频道后：

- 消息列表分页加载，每页 30–50 条（`getChatHistory` 的 `limit` 参数）。
- 支持视频、图片、其他媒体；视频之外的类型只做展示，不单独建导航。
- 按需同步：打开频道时才同步该频道，打开 App 时只同步已参与索引的频道增量。
- 不做后台无条件轮询。

必须存在的状态界面：

| 状态 | 表现 |
|---|---|
| 首次加载 | 骨架屏或明确的加载态，不是空白 |
| 同步中 | 进度 + 已同步条数 |
| 同步完成 | 列表 |
| 空列表 | 「该频道没有可播放的视频」+ 刷新按钮 |
| 网络错误 | 错误文案 + 重试按钮，保留已缓存内容 |
| 授权失效 | 「Telegram 登录已失效」+ 重新登录入口 |

禁止使用虚构频道、假消息或模拟数据填充列表。

## 4. 抖音页（核心）

### 4.1 视觉

- 全屏沉浸，深色优先，但支持浅色 / 深色 / 跟随系统三档（见 §6.5）。
- 视频是视觉主体，占满可用区域。
- 叠加层只有三层，从上到下：
  1. 顶部安全区内：返回或关闭按钮（视入口而定）。
  2. 底部信息区：标题、来源频道、必要播放状态。
  3. 控制层（默认隐藏）：播放/暂停、进度条、时间、横屏按钮、静音。
- **不设右侧竖排操作区。** 没有点赞、评论、分享、收藏、下载的竖向图标列。
- 按钮尺寸不小于 44×44 pt，单手可触达区域为主。
- 处理刘海、底部 Home 指示条；`MediaQuery.padding` 而不是硬编码高度。

视频显示策略：

| 素材 | 显示 |
|---|---|
| 竖屏（9:16 及更窄） | aspect fill，铺满，允许裁掉上下极少量 |
| 方形 | aspect fit，上下留黑，不裁切 |
| 横屏（16:9 及更宽） | 竖屏状态下 aspect fit，完整显示，允许上下留黑 |
| 未知比例 | 先按 fit 显示，拿到 `video.width/height` 后再切换，避免先拉伸再跳变 |

任何情况下不得拉伸变形。

### 4.2 手势

| 手势 | 行为 |
|---|---|
| 向上滑 | 下一个视频 |
| 向下滑 | 上一个视频 |
| 单击 | 显示 / 隐藏控制层 |
| 双击 | 暂停 / 继续 |
| 拖动进度条 | 跳转 |
| 长按 | **无操作**（第 4 步确认：不绑手势，避免与双击、拖动争抢） |

冲突处理：

- 双击识别窗口 250–300 ms；窗口内不触发单击。实现上用 `GestureDetector` 的 `onDoubleTap` + `onTap`，Flutter 的 arena 会保证二选一，不自行实现计时器。
- 垂直拖动优先给上下切换，水平拖动优先给进度条；两者用不同的 `GestureDetector` 区域，进度条只在控制层可见时占位。
- 滑动切换的判定阈值：位移 > 屏幕高度 12% 或速度 > 300 px/s。

### 4.3 信息区

底部显示：

- 视频标题（如果有 caption）
- 来源频道名称
- 消息日期（`yyyy-MM-dd`）
- 播放进度 `mm:ss / mm:ss`（在控制层里）
- 加载阶段文字：「正在准备视频…」/「正在缓冲…」/「无法播放（原因）」

**移除项**（本轮正式确认）：

- 视频时长筛选控件及其全部枚举值 —— 不在任何位置出现。
- 收藏按钮、收藏数据模型、收藏持久化、收藏专用页面。
- 下载按钮、下载任务、下载进度、下载记录、下载管理页面。
- 点赞、评论、分享、关注等无实际功能的社交控件。

### 4.4 横竖屏

- 竖屏视频默认竖屏沉浸播放。
- 横屏视频默认在竖屏页内完整显示（fit），不强制转屏。
- 用户点横屏按钮 → 进入 **iOS 原生横屏**：
  - 通过 `tgmedia/orientation` 通道设置 `UIInterfaceOrientationMask.landscape` 并触发窗口旋转（`ios/Runner/AppDelegate.swift` 已实现，iOS 16+ 用 `requestGeometryUpdate`，iOS 15 用 `UIDevice.setValue`）。
  - 不是把视频画面旋转 90° 假装横屏。
- 退出横屏 → 恢复 `allButUpsideDown`，页面状态（当前视频、播放位置、控制层显隐）保持不变。
- 不支持的方向或系统限制（用户开了系统方向锁）必须有反馈：不静默失败，提示「系统方向锁已开启，无法自动旋转」。
- 真机需验证：进入横屏、退出、横屏中切换视频、横屏中返回、从横屏退出到频道页。

### 4.5 流畅性与资源

| 项 | 要求 |
|---|---|
| 分页 | 每页 30–50 条元数据 |
| 首屏 | 优先播放当前条，不等整页 |
| 预加载 | 最多 1 条相邻；内存告警时关闭预加载 |
| 并发下载 | 同时只保留当前条的下载任务，切走后取消 |
| 旧播放器 | 切换时先 pause + dispose，再建新的（`SinglePlayerController` 已保证） |
| 过期任务 | 结果回来时校验代次，过期直接丢弃（`LatestOnlySlot`） |
| 缩略图任务 | 同一 key 只跑一次（`InFlightRegistry`）；页面退出后不再写 UI |
| 连续切换 | 100 次无泄漏（自动测试已覆盖 100 与 1000 次） |

异常状态：

| 情况 | 表现 |
|---|---|
| 无视频 | 「该频道暂无视频」 |
| 损坏媒体 | 「此视频无法解码」+ 跳过按钮 |
| 网络中断 | 保留已缓冲部分，显示重试 |
| 加载超时 | 15 秒后显示「加载超时」+ 重试 |
| 解码失败 | 同「损坏媒体」，不无限转圈 |

禁止：永远转圈、点击无反应、只改按钮文字不执行操作。

### 4.6 真机 100 次切换测试（第 4 步执行）

自动化已覆盖逻辑层（`test/switch_stress_test.dart`）。真机需要单独记录：

| 记录项 | 方式 |
|---|---|
| 是否崩溃 | 观察 + `idevicesyslog` 或 Console.app |
| 内存峰值 | Xcode Debug Navigator 或 `os_proc_available_memory` 采样 |
| 播放器实例数 | 埋点计数，切换 100 次后应为 1 存活 |
| 卡顿 | `flutter run --profile` 的 frame timing |

## 7. Telegram 登录状态持久化

### 7.1 目标

首次登录成功后，正常关闭并重开 App，不得重新要求手机号与验证码。

### 7.2 实现要点

| 要点 | 现状 |
|---|---|
| TDLib 数据库目录 | `Library/Application Support/tgmedia/secure/tdlib/db`（持久，不在 Caches） |
| 数据库密钥 | Keychain，`tg_tdlib_db_key_v1`，32 字节 hex，`first_unlock_this_device` |
| 客户端复用 | 全 App 一个 `TdClient` 实例；同目录第二个实例会因 `td.binlog` 文件锁失败 |
| 状态判定 | 只看 TDLib 的 `authorizationStateReady`，不看本地布尔值 |
| 启动决策 | `SessionBootPlanner.plan()`，见 §7.3 |

### 7.3 启动决策表

输入：Keychain 是否有密钥、密钥是否合法、`td.binlog` 是否存在、上次授权阶段。

| 密钥 | 数据库 | 阶段 | 动作 |
|---|---|---|---|
| 有，合法 | 有 | `Ready` | 直接进主界面 |
| 有，合法 | 有 | `WaitTdlibParameters` | **等待**，不进登录页 |
| 有，合法 | 有 | 需要输入的任一阶段 | 进登录页，客户端复用 |
| 有，合法 | 有 | `Closed` / `LoggingOut` | 进登录页 |
| 有，合法 | 有 | 未知 | 等待，不猜 |
| 有，非法 | 任意 | 任意 | 阻塞，要求用户决定 |
| 无 | 有 | 任意 | 阻塞，要求用户决定 |
| 无 | 无 | 任意 | 首次登录 |

`WaitTdlibParameters` 到达时数据库还没打开，它不是登出信号。把它当登出，就是「每次冷启动都要输手机号」的原因。

### 7.4 不得做的事

- 不用本地布尔值判断已登录。
- 不把验证码、两步验证密码、API Hash 写进日志、源码或仓库。
- 不随意移动、覆盖、删除 TDLib 数据库。
- 不在密钥缺失时自动生成新密钥去打开旧库（旧库会打不开，而界面看起来像成功了）。
- 登录失败时不显示「已登录」。

### 7.5 退出登录

必须二次确认，文案说明：

- 清除本地会话与媒体索引；
- 不影响 Telegram 云端消息；
- 下次需要重新输入手机号与验证码。

### 7.6 需要真机验证的场景

App 强制退出后重开、设备重启后打开、断网后打开、飞行模式登录失败后恢复、切后台 30 分钟后回来。

## 8. Face ID / Touch ID

### 8.1 定位

应用锁。不是 Telegram 凭据，不能替代 Telegram 登录，不能作为两步验证密码，不参与 TDLib 数据库密钥派生。

### 8.2 默认关闭

- 首次安装、首次启动：Face ID 关闭，应用锁关闭，不弹任何生物识别提示。
- 用户登录 Telegram 后，可在「设置 → 隐私与安全」主动开启。
- 开启前置条件：已设置应用解锁密码。没有密码时开关置灰，点击提示「请先设置应用解锁密码」。
- 开启时先说明用途（一段说明文案 + 继续按钮），再调用系统能力。
- 不得在首次启动强制要求启用。

### 8.3 状态机

```
未启用 ──(设置密码)──> 仅密码 ──(开启生物识别)──> 密码 + 生物识别
   ↑                      ↑                            │
   └──(忘记密码恢复)───────┴────────────────────────────┘
```

解锁判定（`LockEvaluator.decide`）：

| 条件 | 结果 |
|---|---|
| 应用锁未启用 | 不锁 |
| 冷启动且「启动时要求解锁」开启 | 锁 |
| 从后台回来且离开时长 ≥ 自动锁定档位 | 锁 |
| 锁 + 生物识别可用 | 先弹生物识别，密码在背后 |
| 锁 + 生物识别锁定/未录入/不可用 | 直接密码 |
| 生物识别开启但没有密码（只能来自被改坏的存储） | 不锁，避免永久锁死 |

### 8.4 失败与取消

| 结果 | 表现 |
|---|---|
| 成功 | 进入应用 |
| 用户取消 | 停在本页，生物识别按钮仍可点 |
| 系统中断 | 同上 |
| 用户点「使用应用密码」 | 显示密码输入框 |
| 连续失败导致锁死 | 隐藏生物识别按钮，只留密码，并说明「面容 ID 已被系统锁定」 |
| 未录入 | 同上，说明「系统未录入」 |
| 设备无密码 | 同上，说明「设备未设置密码」 |

生物识别失败不得显示「密码错误」——那是两件事，混在一起会误导用户。

### 8.5 密码

- 存储：PBKDF2-HMAC-SHA256，默认 120000 次迭代，16 字节盐，32 字节输出，存 Keychain。
- 校验：恒定时间比较。
- 记录自带迭代次数与盐，将来提高强度不影响旧记录。
- 密码规则：6–128 位，不得全空格，不得含控制字符。
- 连续失败：前 5 次无延迟，之后 5s → 10s → 20s …… 上限 5 分钟。
- 提示词只展示，不参与比对。

### 8.6 忘记密码

唯一路径：**用 Telegram 账号重新验证后重置应用锁**。

- 重置内容：删除应用密码与生物识别开关，保留 Telegram 数据不受影响（但重置流程本身要求重新登录 Telegram，见下）。
- 重置后：重新登录 Telegram，然后要求重设应用密码。
- 不提供「跳过」或「稍后再说」。
- 不提供安全问题等弱凭据。

理由写在这里，避免第 4 步被当成可选项删掉：本地密码一旦忘记，设备上没有任何可信凭据能证明使用者是机主；放行等于应用锁失效，拒绝等于永久锁死。Telegram 账号是使用者真正持有的凭据，是唯一既不弱化也不锁死的选项。

### 8.7 不得做的事

- 不采集、不保存、不上传人脸图像、指纹图像或生物特征模板。
- 不把生物识别结果当 Telegram 密码。
- 不因为开关 Face ID 而清除 Telegram 授权或媒体数据。
- 不在日志里打印生物识别的原始错误码链。

### 8.8 需要真机验证

启用、解锁成功、识别失败、取消、备用解锁、后台锁定、重启后恢复、关闭 Face ID 后 Telegram 仍在线、系统里删除面容后 App 的表现。

## 9. 缓存清理

### 9.1 四个存储区

| 区 | 路径 | 谁能删 |
|---|---|---|
| 临时缓存 | `Library/Caches/tgmedia` | 只能由「清除缓存」删 |
| 用户下载 | `Documents/TGMediaDownloads` | 本轮取消下载功能后不再写入，见 `docs/DOWNLOAD-DEPENDENCY-MAP.md` |
| 媒体索引 | `Library/Application Support/tgmedia/index` | 永不 |
| 账号与会话 | `Library/Application Support/tgmedia/secure` | 永不 |

### 9.2 可清理（白名单）

只有登记过的写入方目录内的文件：

| 目录 | 内容 | 可重新获取 |
|---|---|---|
| `thumb/` | 缩略图 | 是 |
| `player/` | 播放临时文件 | 是 |
| `partial/` | 未完成的分片 | 是 |
| `tdlib_files/` | TDLib 下载池 | 是 |

判定由 `lib/storage/cache_ownership.dart` 完成，规则是**白名单**。

### 9.3 绝不清理

- Telegram 云端消息、频道、媒体（应用没有任何云端删除能力）。
- 用户主动保存的文件。
- 登录授权、Keychain 凭据、TDLib 数据库。
- 媒体索引、账号信息。
- 归属不明或无法确认用途的文件 —— **跳过，并在结果里列出**。

### 9.4 流程

```
点「清除缓存」
  → 盘点（递归列 Caches/tgmedia，逐个 stat）
  → 显示预计释放空间 = 已登记文件总字节
  → 用户确认
  → 逐文件：先过 zone 守卫，再过所有权白名单，再看是否被播放器占用
  → 删除后复查文件确实不存在才计入已释放
  → 报告：实际释放 / 跳过占用 / 跳过未识别 / 越界拒绝 / 失败明细
```

- 任何一步失败都要出现在报告里，不得汇总成「清理完成」。
- 未识别文件不删除，但必须出现在报告和设置页的「未识别文件」行里。
- 不调用任何 Telegram 云端删除 API（实际上根本不存在这样的调用，`TdReadOnlyGuard` 会拦）。

### 9.5 安全测试

已有自动测试覆盖：只删临时区、不动三个受保护区、跳过占用中文件、跳过未识别文件、拒绝符号链接越界、字节只计真删掉的、空区幂等、保护区消失判失败。

第 4 步补充 10 项负向用例（`test/security_negative_test.dart`）：越界删除、符号链接逃逸、未登记目录、占用中文件、假成功（删除无效与索引计数变化两种）、Keychain 缺 key、密码记录被篡改、诊断未脱敏、只读守卫拒绝未分类方法、清理全程不遍历受保护区。
