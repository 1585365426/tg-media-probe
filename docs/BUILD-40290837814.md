## 本轮三件事

### 1. 保持登录（不需要每次重新验证 Telegram）

根因不是 Telegram：TDLib 的 session 一直在
`Library/Application Support/tgmedia/secure/tdlib/db` 里，配置好参数就直接回
`authorizationStateReady`。是 App 从来不问 —— `main()` 只构建不需要客户端的服务，
`TdClient` 只在登录页里创建，所以每次冷启动 `hasClient == false`，频道页显示
"尚未登录"。验证码从来没有被重新请求，被重新要求的是**那个页面**。

- `lib/td/session_restore.dart`：从钥匙串读 `tg_api_id` / `tg_api_hash`，用已存的
  key 打开同一个库，报告授权阶段。key 格式不对就报错，绝不重建（重建会让已有库
  读不开）。`authorizationStateWaitTdlibParameters` 不算结论 —— 它在库打开**之前**
  到达，把它当"已登出"正是每次启动都要输手机号的原因。
- `lib/ui/boot/session_gate.dart`：启动路由先恢复再交接。`restored` 直接进 shell
  且已登录；`needsInteraction` 自动推一次登录页并停在正确步骤，复用**同一个**
  client（开第二个会撞 `error 400: Can't lock file td.binlog`）；`needsLogin` /
  `unavailable` 进 shell 并用 snackbar 说明原因，不再是沉默。
- `lib/ui/boot/lock_gate.dart`：从 `main.dart` 移出，启动路径不再 import 整个根。
- `LoginPage`：接管该 client，已配置过就跳过 `setTdlibParameters`；没交接出去的
  client 在 `dispose` 里释放，不把文件锁留在进程里。

### 2. 清理缓存

- 扫描把每个文件路径和 `layout.tempRoot` 做字符串包含判断。iOS 容器是 symlink，
  列表返回的路径和区根可能在 `/var` 与 `/private/var` 上前缀不一致，于是每个候选
  都判为 unsafe 计入跳过，界面报 0 个 / 0 B，而池里躺着几百 MB。改为以**列出该
  文件的目录**为基准；真正的安全判断仍在删除时由
  `assertDeletableByCacheClear` 逐文件执行（两边都 canonical 化）。
- `scan()` 加 45 秒上限，失败可见可重试，磁贴不会再永久停在"正在统计…"——
  那看起来和死按钮一模一样。
- 存储卡新增「扫描明细」：每个采集目录的绝对路径 + 文件数 + 大小，外加临时缓存根。
  只给"0 B"无法区分"空"和"看错地方"，这个歧义已经耗掉两轮。
- 结果弹窗改为按文件名列出失败项。

### 3. 视频一直加载不出来

范围服务器可以把合法的 206 响应头交给 AVPlayer，然后 TDLib 一个字节都不给。条目
进入 `readyToPlay`，`initialize()` 正常返回，没有任何异常抛出，于是
`activate().timeout()` 永不触发，屏幕停在黑帧：没有转圈、没有百分比、没有报错。

- 首帧看门狗：流式激活后 10 秒内播放位置必须越过 250 ms，否则释放播放器走整段
  下载。进度用 `position` 判定，不用 `isPlaying` / `isBuffering` —— 后者在饿死时
  仍然报乐观值。
- 会话熔断：连续两条没出画面，本进程不再尝试，其余视频不必每条先等 10 秒。
- 阶段文字在 `isInitialized` 之后仍显示：「正在建立本地流…」「正在缓冲第一帧…」
  「正在下载视频（整段下载后才能播放）」。
- 设置 → 播放 → 「边下边播（本地流）」：关掉就完全跳过尝试。默认开启（它是首帧
  变快的唯一手段）；旧配置文件缺这个键时保持开启。

`objective_c.framework`），是 Flutter 构建产物自带的 framework 级签名，不是 app
签名。之前几轮只查了 app 根所以显示 0，这里如实列全。

新字符串在 `Frameworks/App.framework/App` 按 UTF-16LE 全部命中：

```

```

`Runner` 主二进制里没有这些字符串，符合预期：Dart 侧代码都在
`Frameworks/App.framework/App` 里。
